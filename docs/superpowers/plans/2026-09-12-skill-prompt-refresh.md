## Work

1. Inventory canonical paths, symlinks, mirrors, ownership, and existing changes. Audit discovery metadata and conditional loading; distinguish personal sources from managed plugin caches.
2. Shorten overbroad descriptions. Refactor heavyweight entrypoints only where a conditional router reduces real loading; preserve references/assets and fragile invariants. Make process guidance proportional to task risk, avoid duplicate verification and redundant approvals, and retain explicit-only TDD as a requested workflow.
3. Update IssueBot's planning, implementation, and review prompt ownership. Bundle original frontend guidance for UI work, share one maintained policy resource, preserve structured output and trusted local/CI gates, and avoid claiming full native Superpowers orchestration.
4. Validate changed skills and references; use a bounded independent behavioral evaluation for complex process changes. Test IssueBot in coherent increments, then one final relevant suite. Record exact tested trees, failures, limitations, and file/skill changes.
5. Produce the full report, including installed versus staged/upstream-only changes and rollback information. Do not silently replace managed plugins or overwrite dirty personal repositories.

## Implementation decisions

- This is maintenance explicitly authorized by the user; use the supplied skill-creator's proportional workflow instead of old skill rules that mandate repeated pressure tests, universal TDD, or another approval for each safe edit.
- Use the existing validated main commit as the baseline; do not repeat its unchanged full suite merely to initialize a worktree.
- Existing repository release/approval invariants remain authoritative. Prompt improvements are not permission to weaken executable gates or infer publication/deployment authorization.
- External skill directories require the normal sandbox escalation; stage reproducible changes and originals before applying them.
