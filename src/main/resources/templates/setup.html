Webhooks

GitHub webhooks give near-instant issue pickup instead of waiting for the next poll. Polling keeps running as a fallback, so webhooks are optional but recommended.

Payload URL /webhooks/github
Secret SET (value is never displayed — set via the ISSUEBOT_WEBHOOK_SECRET environment variable)

Watched Repositories

Repository Last Webhook Event
owner/repo never
No repositories watched yet.

On GitHub: repo Settings → Webhooks → Add webhook, set the payload URL above, content type application/json, the same secret as ISSUEBOT_WEBHOOK_SECRET, and subscribe to the Issues event. Running locally? GitHub needs a public URL — see the README's webhook tunnel guide (smee.io, cloudflared, etc.).

Quick Start

Next Steps

  1. Go to Repositories and add a GitHub repository to watch.
  2. On your GitHub repo, add the label agent-ready to an issue you want IssueBot to work on.
  3. IssueBot will detect the issue and begin implementation automatically.
  4. Monitor progress on the Dashboard.

Configuration File

IssueBot looks for a config file at ~/.issuebot/config.yml. Below is an example configuration: 

issuebot:
  poll-interval-seconds: 60
  max-concurrent-issues: 3
  work-directory: ${user.home}/.issuebot/repos
  claude-code:
    implementation-model: claude-opus-4-6
    review-model: claude-sonnet-4-6
    max-turns-per-invocation: 30
    timeout-minutes: 10
    review-max-turns: 15
    review-timeout-minutes: 5
  github:
    token: ${GITHUB_TOKEN}
  notifications:
    desktop: true
    dashboard: true
  repositories:
    - owner: your-org
      name: your-repo
      branch: main
      mode: autonomous
      max-iterations: 5
      max-review-iterations: 2
      ci-enabled: true
      ci-timeout-minutes: 15
      security-review-enabled: false
      auto-merge: false
